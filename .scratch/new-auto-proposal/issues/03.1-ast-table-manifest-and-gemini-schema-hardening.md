## What to build

A grounded, schema-hardened AI variable extraction pipeline that eliminates table index drift and outputs complete repeating loop column mappings. 

When a company's briefing is locked and variable extraction is initiated (`POST /api/companies/:id/variables/extract`), the backend pre-inspects `storage/<company_id>/original_quotation.docx` using `docxmlater.Document.loadFromBuffer()`. It inspects `doc.getTables()`, extracts Row 0 headers, row counts, and sample labels, and constructs a ground-truth `LAYER 1.5: DOCUMENT TABLE MANIFEST` injected directly into the Gemini prompt. 

The structured Gemini response schema (`extractionResponseSchema` in `gemini.service.ts`) is updated to include a flattened string array `columns: string[]` under `compound_tables`, allowing Gemini to return explicit column tags without triggering Google Generative AI 400 schema errors. 

Prompt directives strictly enforce that table cell mutations include `row_identifier` (Col 0 label) and `col_index` (column number), and that any variable carrying a `visibility_rule` (like taxes or discounts) must emit `action: "wrap_conditional_row"` rather than `replace_table_cell`. Discovered variables and compound tables with column mappings are persisted to `company_variables` and synchronized with `working_state_json`.

## Acceptance Criteria

- [x] `POST /api/companies/:id/variables/extract` inspects `original_quotation.docx` upfront via `docxmlater` and passes an accurate `LAYER 1.5: DOCUMENT TABLE MANIFEST` (including table indices, column headers, and row counts) into the Gemini context.
- [x] `extractionResponseSchema` in `gemini.service.ts` defines `columns: { type: SchemaType.ARRAY, items: { type: SchemaType.STRING } }` under `compound_tables`.
- [x] Gemini extraction on Fieldstone Studio (`co3_dev`) returns populated column arrays for repeating loops (e.g. `["phase_number", "milestone_title", "deliverable_summary"]` for scope milestones, and `["addon_name", "addon_fee"]` for add-ons).
- [x] Table indices emitted by Gemini match the ground-truth Table Manifest across all benchmark proposals (preventing Fortress IT proposal metadata from pointing to Table 1).
- [x] Variables with visibility rules (such as Texas state tax and annual prepay discount in Northstar `co1_seo`) are emitted with `action: "wrap_conditional_row"` and valid `condition_tag` identifiers.
- [x] Table cell mutations consistently include `row_identifier` and `col_index`.
- [x] All discovered variables and compound tables (including column arrays) persist cleanly in SQLite table `company_variables` and `working_state_json`.
